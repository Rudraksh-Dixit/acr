# ACR dataset catalog

Every dataset ACR can run through the pipeline lives in `catalog.json`.
Each entry states its provenance up front:

| label | meaning |
| --- | --- |
| `synthetic` | generated by ACR's own scenario emitters (deterministic, seed 42) |
| `real (source name)` | externally sourced telemetry; source is named in the label |

**Ground truth policy:** only synthetic scenarios carry per-event ground-truth
tags (`gt_id`), so only they get precision/recall/F1. For every `real (...)`
dataset the evaluation endpoints report detections but state
*"no ground truth, precision/recall not computed"* — numbers are never invented.

## Fetching / verifying

The bundled files above are committed, so the app works offline out of the
box. To re-download or verify:

```bash
python scripts/fetch_datasets.py           # download + sha256 + convert
python scripts/fetch_datasets.py --check   # verify local files, no network
python scripts/fetch_datasets.py --force   # re-download everything
python scripts/fetch_datasets.py --dataset evtx-attack-samples
```

The script only downloads, hashes, unzips and re-serialises files — dataset
content (including any URLs inside it) is never executed or opened. A sha256
mismatch aborts that dataset with exit code 1. Raw upstream artifacts land in
`data/datasets/sources/` (gitignored, reproducible).

## Honest skip reporting

Rows ACR cannot map are never dropped silently. The adapters emit structured
issues (e.g. *"row has no recognisable timestamp/host/event id fields"*) and
the normaliser reports each skipped record with its reason
(*"unable to determine event_type; record skipped"*), so run reports show
`N stored / M skipped (reasons)` exactly as observed. Example: the OTRF
sample contains event ids ACR deliberately does not map (10, 4656, 4658,
4690, 4799) — 60 of 118 rows are reported as skipped with those reasons.
